# Выгрузка журналов Bybit

Python 3.9+, устанавливать библиотеки не нужно. Запуск из корня проекта:

```sh
python3 scripts/bybit_export.py --start 2025-01-01
```

Скрипт скрыто запросит API key и API secret. Используйте системный HMAC API-ключ
с доступом только на чтение соответствующих счетов. Не отправляйте секрет в чат.
Альтернатива: переменные окружения `BYBIT_API_KEY` и `BYBIT_API_SECRET`.
RSA-ключи не поддерживаются.

По умолчанию выгружаются последние 729 дней до момента запуска. Например,
весь 2025 год (конец периода **не включён**, даты без часового пояса — UTC):

```sh
python3 scripts/bybit_export.py --start 2025-01-01 --end 2026-01-01 --output /tmp/bybit-2025
```

Результат: новая папка `bybit-export-YYYYMMDD-HHMMSS` с `unified.csv`,
`funding.csv` и `manifest.json`. CSV в UTF-8 BOM, разделитель — запятая.
Все поля API сохраняются, добавляются `source` и `time_utc`; денежные значения
не преобразуются во float. При импорте в Excel задавайте идентификаторам текстовый
тип, чтобы Excel не округлил их. Строки идут в порядке получения от API.

Запрашиваются все валюты и типы операций без фильтров, недельными интервалами
со всеми страницами. Чтобы получить один журнал, добавьте `--source funding`
или `--source unified`. Для регионального аккаунта используйте `--base-url`
с официальным API-хостом вашего региона. Ключ передаётся именно этому хосту.

## Границы полноты

- Unified: API документирует хранение до **двух лет**. Более старые операции
  нельзя восстановить разбивкой запросов. Для старого Funding можно явно
  задать `--start`; документация не обещает определённую глубину хранения.
- Это журналы движений Unified и Funding для аккаунта данного ключа, а не
  полный архив всех продуктов Bybit: отдельные P2P-заказы, карточные операции,
  детали блокчейн-депозитов/выводов, история Classic/pre-upgrade и другие
  субаккаунты здесь не запрашиваются. Движения, отражённые в этих двух журналах,
  попадут в CSV, но отдельные детали операций могут требовать других API.
- Перевод между своими счетами может иметь запись в обоих CSV. Это две стороны
  перевода; не считайте их независимыми доходами/расходами.
- Успешный ответ API не доказывает наличие всей истории: сервер может не вернуть
  старые записи. Сверьте известные операции с CSV. Свежие записи могут задерживаться.
- При ошибке одного журнала второй всё равно выгружается. Код выхода 1 и
  `complete: false` в manifest обозначают незавершённую выгрузку. Файлы
  `*.partial.*` содержат только полученную часть. При прерывании статус также
  остаётся незавершённым. Повторный запуск делайте в новую папку; автоматического
  продолжения нет. Существующую папку скрипт не перезаписывает.
