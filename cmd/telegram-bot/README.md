# Telegram-бот Finforme

`@finforme_bot` показывает BTC/USD (Coinbase), USD/RUB и EUR/RUB (ЦБ РФ),
NVDA/USD и NBIS/USD (Yahoo Finance), YDEX/RUB (MOEX ISS).
Команды: `/start`, `/help`, `/rate`, `/rates`, `/chart`.
Без аргументов `/rate` и `/rates` показывают только BTC/USD, USD/RUB и EUR/RUB.
Акции запрашиваются отдельно: `/rate NVDA`, `/rate NBIS`, `/rate YDEX`.
Допускаются полные пары (`/rate NVDA/USD`) и нижний регистр.

Бот получает котировки через публичный HTTPS API сайта. Подключение к MariaDB
и финансовый API-токен ему не нужны. Для каждой пары выбирается явный источник;
другие источники не заменяют выбранные котировки. Акции выводятся отдельными
строками с источником и временем котировки в МСК (или датой закрытия, если
точное время отсутствует). YDEX приходит с задержкой биржи 15 минут.
Yahoo использует `regularMarketPrice`: цена основной сессии, без премаркета
и постмаркета. Это неофициальный интерфейс; при сбое импорта API продолжает
отдавать последнее сохранённое значение с исходной датой и временем.

## Графики котировок

Бот отправляет PNG размером 1200×720 прямо в чат:

```text
/chart help            # справка по графикам и примеры
/chart                 # USD/RUB за последние 14 дней
/chart EUR 30          # EUR/RUB за 30 дней
/chart NVDA 30         # NVIDIA за 30 дней
/chart NBIS 2w         # Nebius Group за 2 недели
/chart YDEX 30         # Яндекс за 30 дней
/chart BTC/USD 2w      # BTC/USD за 2 недели
/chart USD/ARS 14      # доллар к песо, Blue Sell
/chart RUB/ARS 14      # рубль к песо, Blue Sell × ЦБ РФ
```

Период — от 2 до 365 календарных дней включительно, до сегодняшнего дня по
Москве. Можно указать число дней, `14d`/`14д` или число недель `2w`/`2н`.
Сокращения `USD`, `EUR`, `BTC` означают USD/RUB, EUR/RUB, BTC/USD;
`NVDA`, `NBIS`, `YDEX` — NVDA/USD, NBIS/USD, YDEX/RUB.
История акций накапливается по одной последней котировке на торговую дату.
Прошедшие дни можно заполнить дневными ценами закрытия через `-history-days`. Пока нет двух дат, график объясняет, что данных недостаточно.

История берётся из соседнего API `/api/currency/charts?days=N`. Источники
выбираются явно; будущие даты исключаются. График содержит фактические даты
и число сохранённых котировок, последнее значение и изменение между первой
и последней доступной точкой. Пропущенные наблюдения не добавляются;
линия соединяет реальные точки. Если точек меньше двух, бот отвечает текстом.

## API котировок

`GET https://finfor.me/api/currency/rates` возвращает JSON:

```json
{
  "rates": [
    {
      "code": "USD/RUB",
      "name": "Доллар США",
      "rate": 82.5486,
      "source": "cbr",
      "rate_date": "2026-11-11"
    }
  ]
}
```

Это последняя сохранённая публикация для каждой пары и источника, включая
объявленный ЦБ курс на следующий день. `rate_date` сохраняет дату источника.
Для акций API также возвращает `quoted_at` — время сделки в RFC3339 (UTC).
У цены предыдущего закрытия MOEX известна только `rate_date`, поэтому
`quoted_at` отсутствует. Время импорта не подставляется вместо времени сделки.
Пустая база возвращает `{"rates":[]}`; недоступность базы — HTTP 503.
В ответе нет счетов, операций или других пользовательских данных.
Кэширование ответа разрешено на 30 секунд.

Запрос бота ограничен пятью секундами и ответом в 1 MiB. При ошибке API бот
сообщает, что котировки получить не удалось; локальная база или устаревший
кэш вместо ответа не используются.

## Импорт акций на сервере сайта

`import-stock-rates` входит в образ сайта и запускается независимо от валютных
импортеров каждые 15 минут по `scripts/finforme.cron`. API-ключи не нужны.
Ошибка одного тикера не мешает сохранить остальные; процесс возвращает
ненулевой код при любой ошибке. Старый ответ не перезаписывает более свежую
котировку той же торговой даты.

Первое развёртывание: обновите сайт (он добавит nullable-колонку `quoted_at`),
выполните `docker exec finforme ./import-stock-rates`, обновите
`/etc/cron.d/finforme` из `scripts/finforme.cron`, затем обновите бот.
`make deploy` сам расписание cron не устанавливает.

Проверка источников без записи в базу:

```bash
go run ./cmd/import-stock-rates -preview
# Дневные цены за 31 прошедший день; только просмотр:
go run ./cmd/import-stock-rates -history-days 31 -preview
# Заполнить отсутствующие даты на сервере:
docker exec finforme ./import-stock-rates -history-days 31
```

`-history-days N` принимает 1–365 календарных дней до сегодняшнего дня по МСК.
Текущая биржевая дата также исключается. Yahoo использует `close`, без
дивидендной корректировки `adjclose`; MOEX — `close` дневных свечей TQBR.
Пропущенные наблюдения не заполняются искусственно. У исторических цен нет
точного времени сделки, поэтому `quoted_at` отсутствует. Запись выполняется
транзакцией для каждого тикера, только для отсутствующих дат; повторный запуск
не меняет существующие цены и время котировок. Обычный cron продолжает
импортировать только последние котировки.

HTTPS MOEX проверяется отдельным клиентом с корнем Russian Trusted Root CA,
полученным с официального сайта Госуслуг и встроенным в бинарник.
Системное хранилище сертификатов и HTTPS-клиенты других источников не меняются.

## Сервер в Германии

Бот работает на `firej@45.144.233.69` в отдельном Compose-проекте
`finforme-bot`, каталог `/opt/finforme-bot`. Он обращается к Telegram напрямую.
Сайт, база и импорт курсов остаются на `firej.org`.

Настройки `/opt/finforme-bot/.env` (владелец root, права `0600`):

```dotenv
TELEGRAM_BOT_TOKEN=<существующий токен бота>
CURRENCY_RATES_URL=https://finfor.me/api/currency/rates
```

Токен устанавливается отдельно и не попадает в исходники, образ или архив
деплоя. Копировать `.env` веб-сервера на сервер бота не нужно.

```bash
make deploy-bot                    # только бот на BOT_DEPLOY_HOST
make deploy-all                    # сначала сайт/API, затем бот
make deploy-bot BOT_DEPLOY_HOST=firej@45.144.233.69
```

`scripts/deploy-bot.sh` собирает Linux amd64-бинарник, загружает минимальный
образ и проверяет API котировок и Telegram перед запуском. `BOT_PREPARE_ONLY=1`
подготавливает и проверяет сервис без запуска polling — для переноса сначала
остановите старый экземпляр, затем запускайте новый. Одновременный polling
двух экземпляров одного бота недопустим.

Диагностика на сервере:

```bash
cd /opt/finforme-bot
sudo docker compose --env-file .env ps
sudo docker compose --env-file .env run --rm --no-deps finforme-bot -check
sudo docker logs --tail 20 finforme-bot
```

`-check` проверяет авторизацию Telegram и наличие всех шести нужных котировок,
не забирая обновления и не отправляя сообщения. Эта же команда используется
в Docker healthcheck. Контейнер запускается от непривилегированного
пользователя, с файловой системой только для чтения и `restart: unless-stopped`.
Таймаут авторизации Telegram — 15 секунд, запросов polling — 75 секунд.
Токен скрывается в логах приложения и Telegram SDK, включая сетевые ошибки.

## Локальная разработка

Задайте `TELEGRAM_BOT_TOKEN` и выполните `make bot-run` или
`go run ./cmd/telegram-bot`. По умолчанию используется публичный API `finfor.me`.
Для локального сайта задайте
`CURRENCY_RATES_URL=http://localhost:8080/api/currency/rates`.

Предпросмотр с реальными данными, без токена и обращения к Telegram:

```bash
go run ./cmd/telegram-bot -chart-preview 'USD/RUB 14' > /tmp/finforme-chart.png
```

В локальном Compose бот включается явно: `docker compose --profile bot up -d`.
Он обращается к `http://app:8080/api/currency/rates`.
Не запускайте локальный polling с production-токеном одновременно с сервером.

Проверки: `go test -race ./cmd/telegram-bot`; тестовые ответы Telegram и API
обслуживаются локально, настоящие сообщения не отправляются.
