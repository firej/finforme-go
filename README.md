# Finforme - Personal Finance Manager

Веб-приложение для управления личными финансами с поддержкой двойной записи (double-entry bookkeeping).

## Технологии

- **Backend**: Go 1.25+
- **Frontend**: HTML + htmx + Chart.js для динамических обновлений
- **База данных**: MariaDB
- **Стиль**: Tailwind CSS
- **Контейнеризация**: Docker / Podman

## Возможности

- ✅ Управление счетами с иерархической структурой
- ✅ Транзакции с двойной записью (дебет/кредит)
- ✅ Поддержка нескольких валют
- ✅ Теги для категоризации транзакций
- ✅ Аутентификация пользователей
- ✅ Импорт данных из GnuCash SQLite
- ✅ Резервная копия в JSON и восстановление из неё
- ✅ Динамический интерфейс с htmx (без перезагрузки страниц)
- ✅ Курсы валют USD/RUB и EUR/RUB с графиками (данные ЦБ РФ)

## Быстрый старт

### Запуск через Docker Compose (рекомендуется)

```bash
# Один раз создайте секрет и сохраните его в защищённых настройках окружения.
export SESSION_SECRET="$(openssl rand -hex 32)"

# Запустить приложение с MariaDB
make up

# Или напрямую
docker-compose up -d
```

Приложение будет доступно по адресу: http://localhost:8000

### Локальная разработка

```bash
# Укажите ранее сохранённый SESSION_SECRET в окружении.
# Запустить только MariaDB, приложение запустить локально
make dev

# Или по шагам:
make db-only          # Запустить MariaDB
go run cmd/server/main.go  # Запустить приложение
```

### Полезные команды

```bash
make up        # Запустить всё через docker-compose
make down      # Остановить
make logs      # Посмотреть логи
make db-shell  # Открыть консоль MariaDB
make rebuild   # Пересобрать и перезапустить контейнеры
```

## Конфигурация

Приложение настраивается через переменные окружения:

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `PORT` | Порт приложения | `8000` |
| `DATABASE_DSN` | DSN для подключения к MariaDB | `finforme:finforme@tcp(localhost:3306)/finforme?parseTime=true&charset=utf8mb4` |
| `SESSION_SECRET` | Случайный секрет не короче 32 байт | Обязателен для HTTP-сервера, значения по умолчанию нет |
| `SECURE_COOKIE` | Использовать secure cookies | `false` |
| `PUBLIC_URL` | Внешний origin для OAuth; в production задайте `https://finfor.me` | `http://localhost:8080` |

### Обновление безопасности входа

Перед обновлением сохраните резервную копию базы и задайте `SESSION_SECRET`
в окружении HTTP-сервера. Для Docker Compose можно сохранить его в защищённом
файле `.env` рядом с **фактически используемым** compose-файлом (на сервере это
может быть `/opt/traefik`), либо экспортировать перед запуском Compose.
Секрет нельзя добавлять в Git; не генерируйте его заново при каждом запуске.
При развёртывании через существующий `/opt/traefik` замените также старое
жёстко заданное значение в его compose-конфигурации.

Сервер автоматически добавляет поля версии сессии и восстановления пароля.
Ошибки этих миграций останавливают запуск. После первого обновления старые
cookie без версии перестанут действовать: потребуется повторный вход.
Команды импорта курсов не требуют `SESSION_SECRET`.

Обычная смена пароля завершает остальные браузерные сессии, сохраняя текущую.
API-токены при обычной смене пароля сохраняются. Сброс через администратора
отзывает все сессии **и API-токены** и выдаёт случайный одноразовый пароль,
который показывается только в ответе на сброс. Передайте его пользователю
безопасным способом. В течение 30 минут пользователь должен войти и задать
новый пароль; до этого финансы, админка и API недоступны. Временный пароль
расходуется при первом успешном входе. При утрате сессии или истечении срока
администратор выполняет сброс повторно. Самостоятельный сброс администратора
и сброс демо-пользователя запрещены; для своего аккаунта есть смена пароля.

Браузерные запросы изменения данных защищены проверкой происхождения запроса.
Прокси должен сохранять исходный `Host`. API/MCP-клиенты без браузерных
заголовков используют Bearer-токен как прежде.

### Сохранность финансовых операций

Счёт с операциями удалить нельзя — используйте признак «Скрытый» в настройках.
Валюту такого счёта менять также нельзя: для другой валюты создайте отдельный
счёт. Удаление пустых счетов и редактирование их настроек сохранены.

Форма операции с нестандартным распределением (не ровно две проводки,
одна списания и одна зачисления) позволяет менять только описание, комментарий, дату и
теги и показывает все проводки без редактирования сумм. Обычное сохранение
через API/MCP тоже отказывается заменять такую операцию двумя проводками.
Для безопасной правки реквизитов любой операции используйте:

- `POST /api/v1/finance/transaction/metadata`: `id`, `post_date`, `description`, `tags`, необязательный `comment`.
- MCP `update_transaction_metadata`: `id`, `date`, `description`, `tags`, необязательный `comment`.

Описание и теги можно очистить пустой строкой; проводки сохраняются полностью.
При создании или полном редактировании простой операции суммы должны быть
положительными, конечными и с точностью до копеек, а счета — разными.
Для одной валюты суммы равны; для разных валют обязательно явно передавать
`value_target` в HTTP API или `amount_to` в MCP. Явный ноль недопустим.

Проверки и запись выполняются в одной транзакции; финансовые изменения одного
пользователя последовательно блокируют его строку, чтобы параллельные запросы
не обходили ограничения. Импорт и восстановление используют ту же блокировку.

Регрессионные проверки: `go test -race ./...`. Для проверки на **отдельной
тестовой MariaDB** задайте `FINFORME_TEST_MYSQL_DSN` и выполните
`go test ./internal/handlers -run 'TestAuth|TestFinance' -count=1`.
Тестам нужны права создания баз: каждый тест создаёт и затем удаляет свою
базу с префиксом `finforme_auth_test_`. Рабочую MariaDB для этого не используйте.

### Отчёт за месяц и общий капитал

На дашборде можно выбрать календарный месяц и посмотреть доходы, расходы и
разницу по каждой валюте отдельно, с категориями и сравнением с предыдущим
полным месяцем. Для текущего месяца показано предупреждение о неполном периоде.
Переводы между активами и погашение основного долга не считаются расходами;
возвраты уменьшают расходы. Нажатие на категорию открывает её операции за
выбранный месяц. Валюта отчёта сохраняется при переключении месяцев.

Общий капитал — оценка активов за вычетом обязательств на сегодняшнюю дату.
Скрытые счета включены, будущие операции исключены, контейнеры не суммируются
повторно. Валюту оценки можно переключать; по умолчанию выбирается RUB, затем
USD, EUR, ARS или первая доступная валюта. Разбивка остатков, источники и даты
курсов находятся в «Остатки по валютам и курсы».

Пересчёт использует только серии с явной привязкой к валютам в админке:
последнюю котировку не позже сегодняшней даты и не старше 14 дней. Поддержаны
обратные и кросс-курсы; выбирается путь с наименьшим числом пересчётов. Для пар
с ARS предпочтителен Blue (продажа/кросс), для остальных — ЦБ РФ, затем свежий
доступный источник. Источник используемой пары можно изменить в деталях.
Если выбранный источник недоступен, замена сопровождается сообщением.
Без подходящего курса остаток остаётся в разбивке, но исключается из общей
суммы; такая оценка явно помечена как неполная.

Курсы и промежуточные результаты считаются точными рациональными числами.
Активы и обязательства каждой валюты округляются до копеек только после полного
пересчёта, затем складываются в итог. Оценка не изменяет проводки и историю.

### Помесячный прирост капитала

На дашборде показаны последние 12 календарных месяцев, включая текущий по
сегодняшнюю дату. Каждый столбец открывает подробный отчёт выбранного месяца.
Прирост — разница активов за вычетом обязательств между началом и концом месяца,
в выбранной валюте оценки. Для каждой границы используются исторические курсы
не старше 14 дней; будущие котировки и будущие операции не участвуют.
Если полной оценки на одной из границ нет, вместо прироста показан пропуск.
Неполные суммы не сравниваются друг с другом.

В деталях приведены точные остатки, прирост и курсы каждой границы. Изменение
остатков рассчитывается по курсам начала месяца; курсовая часть — разница
оценок конечных остатков по конечным и начальным курсам. Это разложение изменения
учётного капитала, а не инвестиционная доходность. Оно включает начальные
балансы и корректировки. Если курс новой валюты на начало месяца недоступен,
общий прирост может быть известен, а его разложение показано как недоступное.
Источники фиксируются для всего периода, включая выбранные по умолчанию: отсутствие его котировки
не приводит к незаметной замене на другой источник.

Остатки формируются одной агрегацией проводок за период и ранее; история курсов
загружается одним запросом. Переводы между активами, получение и погашение
основной суммы долга сами по себе не увеличивают чистый капитал.

### Постоянные заметки MCP (memory)

В «Настройки → Память ассистента» пользователь может просматривать, создавать,
редактировать и удалять свои заметки. Интерфейс и MCP используют одну память;
изменения сразу доступны обоим. В списке есть поиск по префиксу ключа и страницы.

MCP хранит контекст между сессиями в таблице `user_memory`, отдельно для каждого
пользователя. Таблица создаётся при запуске приложения. Пользователь определяется
по API-токену или OAuth-токену; передать чужой `user_id` инструментам нельзя.

- `list_memory`: список ключей и времени обновления; необязательные `prefix`,
  `limit` (по умолчанию 50, максимум 100), `offset`. `has_more` сообщает о следующей
  странице. Префикс буквальный; сортировка по ключу.
- `get_memory`: чтение полного содержимого заметки по `key`.
- `save_memory`: сохранение `key` и `content`; существующая заметка заменяется
  целиком. При параллельных сохранениях действует последнее выполненное изменение.
- `delete_memory`: удаление по `key`; `deleted=false`, если заметки уже нет.

Ключ: 1–128 символов `a-z`, `0-9`, `.`, `_`, `/`, `-`; первый символ — буква или
цифра. Содержимое: до 16000 символов UTF-8, не пустое. Время обновления — UTC.
Например, `save_memory` с `{"key":"preferences.currency","content":"Основная валюта отчётов — RUB"}`.
В новой сессии агент может найти ключ через `list_memory` и прочитать `get_memory`.

OAuth с `finforme:read` допускает только чтение, для сохранения и удаления нужен
`finforme:write`. При удалении пользователя его заметки удаляются вместе с ним.
Заметки не входят в финансовую JSON-копию и не изменяются при восстановлении
финансов; для резервирования памяти нужна копия базы MariaDB.

### Комментарии к транзакциям

В формах операции есть отдельное многострочное поле «Комментарий» для расчётов
курсов, данных выписки и уточнений. Описание остаётся кратким назначением.
Комментарий доступен и при редактировании сложных операций без изменения проводок.
Максимальная длина — 16000 символов; переносы строк сохраняются.

HTTP API сохранения операции и её реквизитов принимает необязательное поле
`comment`. MCP `create_transaction`, `update_transaction` и
`update_transaction_metadata` принимают такое же поле. При обновлении пропуск
поля сохраняет существующий комментарий, пустая строка очищает его.
В JSON-списке операций и MCP `get_transaction` комментарий возвращается отдельно
от `description`. Поиск по описанию продолжает искать только в описании.

Колонка `transactions.comment` добавляется при запуске сервера; старые операции
получают пустой комментарий при чтении. Ошибка миграции останавливает запуск.
JSON-копии версии 3 сохраняют комментарии и требуют обновлённого приложения
для восстановления. Копии версий 0–2 остаются совместимыми; отсутствующий
комментарий восстанавливается пустым. Импорт старых данных не переносит части
описания в комментарий автоматически.

### Валютные итоги и CSV

Дашборд показывает отдельную строку для каждой валюты: активы, обязательства,
чистый капитал, доходы и расходы. Конвертации и общего итога разных валют нет.
В дереве счетов и боковой панели родитель показывает суммы по валютам своих
потомков, включая скрытые счета. Суммы отдельных счетов и последних операций
на дашборде также подписаны валютой.

Формат MCP `get_report` изменён: прежние скалярные `total_income`,
`total_expense`, `net` на верхнем уровне удалены. Вместо них ответ содержит
`totals`: массив объектов `{currency, total_income, total_expense, net}`.
Каждая категория в `income` и `expense` содержит `currency`.
Пустой отчёт возвращает пустой массив итогов. Клиентам, которые читали старые
поля, нужно перейти на `totals`.

В `list_accounts` поле `balance` остаётся собственным балансом счёта в
`currency`; новое `balances` содержит суммы счёта вместе с потомками отдельно
по валютам (`[{currency, amount}]`). Скрытые потомки входят в эти суммы,
даже когда `include_hidden=false` скрывает их отдельные строки.

CSV-импорт работает с одной валютой за раз. «Дисбаланс» подбирается по валюте
и при необходимости создаётся как `Дисбаланс-USD`, `Дисбаланс-RUB` и т. п.
Второй счёт должен быть в валюте исходного; обмен валют вносите через форму
операции с двумя суммами. Если в CSV выбрана колонка «Валюта», её значения
проверяются и в превью, и при сохранении. Без этой колонки суммы считаются
заданными в валюте исходного счёта. При изменении исходного счёта сформируйте
превью заново. Ошибочная строка при сохранении откатывает весь пакет.

## База данных

Приложение использует MariaDB с автоматической инициализацией схемы при первом запуске.

### Основные таблицы

- `users` - пользователи системы
- `commodities` - валюты и товары
- `accounts` - счета пользователей
- `transactions` - финансовые транзакции
- `splits` - записи дебета/кредита для транзакций
- `currency_rates` - исторические курсы валют (ЦБ РФ)

## Импорт данных

### Из GnuCash

1. Экспортируйте данные из GnuCash в формат SQLite
2. Перейдите в раздел "Настройки" в приложении
3. Загрузите файл SQLite через форму импорта
4. Данные будут автоматически импортированы с сохранением структуры счетов и транзакций

## Резервная копия

**Настройки → Резервная копия**:

- **Экспортировать JSON** — скачивает файл `finforme-backup-ГГГГ-ММ-ДД.json` со всеми
  счетами (включая иерархию и валюты) и транзакциями со сплитами.
- **Восстановить** — загружает такой файл обратно. Два режима:
  - «Заменить» — текущие счета и транзакции удаляются, данные берутся из файла;
  - «Добавить» — данные из файла дописываются к существующим.

ID из файла при восстановлении переназначаются, ссылки (родительский счёт, счёт сплита)
пересчитываются. Валюта, которой нет в справочнике, создаётся автоматически.

Тот же формат доступен через API — удобно для автоматических бэкапов по cron:

```bash
curl -H "Authorization: Bearer $FINFORME_TOKEN" \
  https://finfor.me/api/v1/finance/export/json -o backup.json

curl -H "Authorization: Bearer $FINFORME_TOKEN" \
  -F "file=@backup.json" -F "mode=replace" \
  https://finfor.me/api/v1/finance/import/json
```

## API Endpoints

### Аутентификация
- `GET /accounts/login/` - страница входа
- `POST /accounts/login/` - вход в систему
- `GET /accounts/logout/` - выход из системы
- `GET /accounts/register/` - страница регистрации
- `POST /accounts/register/` - регистрация нового пользователя

### Финансы
- `GET /finance/` - главная страница (список счетов)
- `GET /finance/account/{id}` - просмотр транзакций счета
- `GET /finance/account/{id}/edit` - редактирование счета
- `GET /finance/transaction/{account_id}/{tx_id}` - просмотр транзакции
- `GET /finance/settings` - настройки и импорт данных

### API
- `POST /api/v1/finance/account/save` - сохранение счета
- `POST /api/v1/finance/transaction/save` - сохранение транзакции
- `POST /api/v1/finance/welcome/import` - импорт из GnuCash
- `GET /api/v1/finance/export/json` - резервная копия всех данных (JSON-файл)
- `POST /api/v1/finance/import/json` - восстановление из резервной копии
  (поля `file` и `mode`: `replace` или `merge`)

## API-токены

Программный доступ к `/api/v1/…` и MCP-серверу работает по токенам.

1. Откройте **Настройки → API-токены** и создайте токен (показывается один раз,
   в БД хранится только SHA-256 хеш).
2. Передавайте токен в заголовке `Authorization: Bearer <токен>` — работает
   для всех эндпоинтов `/api/v1` наравне с cookie-сессией.

```bash
# Список счетов
curl https://finfor.me/api/v1/finance/accounts/get \
  -H "Authorization: Bearer finforme_XXXX"

# Транзакции с фильтрами: account_id, from, to, tag, search, limit, offset
curl "https://finfor.me/api/v1/finance/transactions/get?from=2026-07-01&tag=продукты" \
  -H "Authorization: Bearer finforme_XXXX"
```

## MCP-сервер (Codex, Claude и другие клиенты)

Приложение отдаёт MCP-сервер (Streamable HTTP, stateless) на `/mcp`.
Авторизация — OAuth через вход в браузере или существующий API-токен.
Можно просматривать счета, добавлять транзакции и строить отчёты.

### Подключение

**Codex — без ручного копирования токенов:**

```bash
codex mcp add finforme --url https://finfor.me/mcp
codex mcp login finforme
```

В открывшемся браузере войдите в finfor.me и подтвердите доступ. По умолчанию
выдаётся только чтение; для управления счетами и операциями отметьте разрешение
на запись. Адрес возврата и название приложения видны перед подтверждением.
Существующую настройку с постоянным заголовком Authorization сначала удалите
или замените подключением без этого заголовка.

В других MCP-клиентах с поддержкой OAuth добавьте URL `https://finfor.me/mcp`
и выполните вход. Для этого сервер поддерживает автоматическую регистрацию
публичных клиентов (DCR, `token_endpoint_auth_method: none`); CIMD пока не реализован.

**Подключение с API-токеном (по-прежнему поддерживается), Claude Code:**

```bash
claude mcp add --transport http finforme https://finfor.me/mcp \
  --header "Authorization: Bearer finforme_XXXX"
```

**Локальная разработка** — тот же способ, но URL `http://localhost:8080/mcp`.

Проверить подключение можно запросом: «покажи мои счета в finforme».

### Настройка OAuth на сервере

`PUBLIC_URL` — канонический внешний адрес сервера без пути, например
`https://finfor.me`. За прокси он должен совпадать с адресом, используемым клиентом;
Host и X-Forwarded-Host не используются для построения OAuth-ссылок.
По умолчанию: `http://localhost:8080`; HTTP разрешён только для loopback.
В production compose уже задан `PUBLIC_URL=https://finfor.me`.
При запуске автоматически создаются таблицы `oauth_clients`, `oauth_grants`,
`oauth_codes`, `oauth_tokens`. Существующие API-токены не мигрируются.

Поток: Authorization Code + PKCE S256, одноразовый код на 5 минут,
многоразовый access token до конца срока подключения (90 дней с момента согласия).
Refresh-токены не выдаются и обновление через `refresh_token` не поддерживается.
После истечения срока требуется новое согласие. В БД хранятся только хеши
кодов и токенов. Повторное использование уже обменённого кода (с корректным PKCE)
отзывает всё подключение. После перехода со старой схемы подключитесь заново:
срок ранее выданных токенов не меняется, отозванные разрешения не восстанавливаются.

OAuth-токены действуют только на `/mcp`; для REST API используйте API-токены.
Права `finforme:read` / `finforme:write` проверяются сервером. При ограничении
доступа чтением инструменты записи недоступны даже при прямом вызове.
Смена версии сессии при смене/сбросе пароля, блокировка пользователя или отзыв
подключения прекращают доступ и обновление токенов.

Отзыв: **Настройки → Подключённые приложения → Отозвать доступ**.
Демо-пользователь не может выдавать OAuth-доступ.

Служебные endpoints: `/.well-known/oauth-authorization-server`,
`/.well-known/oauth-protected-resource/mcp`, `/oauth/register`, `/oauth/authorize`,
`/oauth/token`, `/oauth/revoke`. Регистрация ограничена 30 запросами в минуту
на процесс и 10 000 зарегистрированных клиентов в БД; для публичного сервиса
дополнительно можно ограничить частоту запросов на reverse proxy.

Проверка OAuth: `go test ./internal/handlers -run TestOAuth` включает
автоматическое подключение официальным MCP SDK. Для проверки на MariaDB
задайте `FINFORME_TEST_MYSQL_DSN` тестового сервера с правом CREATE DATABASE:
тесты создают и удаляют собственные временные базы.

### Инструменты

| Инструмент | Описание |
|------------|----------|
| `list_accounts` | Счета с балансами и валютой |
| `list_commodities` | Валюты и их ID для создания счетов |
| `get_account` | Параметры одного счёта, включая родителя и описание |
| `create_account` | Создать счёт или категорию: name, account_type, commodity_id; опционально parent_id, description, hidden, placeholder |
| `update_account` | Частично изменить счёт по id; пропущенные поля сохраняются |
| `delete_account` | Удалить пустой счёт без операций и дочерних счетов |
| `list_transactions` | Транзакции с фильтрами (счёт, даты, тег, поиск, пагинация) |
| `get_transaction` | Одна транзакция со сплитами (дебет/кредит) |
| `create_transaction` | Создать транзакцию: `from_account_id` → `to_account_id`, суммы в валюте счёта, поддержка кросс-валютных (`amount_to`) |
| `update_transaction` | Обновить транзакцию по id |
| `delete_transaction` | Удалить транзакцию (необратимо) |
| `get_report` | Доходы/расходы по категориям и итогам отдельно для каждой валюты |
| `get_currency_rates` | Актуальные курсы валют с дневным изменением |

Все инструменты работают строго в рамках пользователя, которому принадлежит
токен. Отозвать доступ можно удалением токена в настройках.

Для создания счёта сначала получите ID валюты через `list_commodities`.
Например: `create_account` с `{"name":"Накопления","account_type":"BANK","commodity_id":1}`
(используйте фактический ID нужной валюты). Допустимые типы: ASSET, CASH, BANK,
LIABILITY, INCOME, EXPENSE, EQUITY. Родитель должен быть контейнером;
`parent_id: 0` снимает родителя. `list_accounts` возвращает `parent_id` и `commodity_id`.
Чтобы скрыть счёт с историей, вызовите `update_account` с `{"id":123,"hidden":true}`;
`false` снова показывает его. Валюту счёта с операциями менять нельзя.
Системные ROOT-счета не редактируются и не удаляются через MCP.

## Курсы валют

Раздел `/currency/` показывает курсы USD/RUB и EUR/RUB с графиками за последние 14 дней.
Данные хранятся в таблице `currency_rates` и обновляются отдельными скриптами.

### Первоначальный импорт исторических данных

После деплоя нужно однократно загрузить исторические данные. Скрипт запускается
**внутри контейнера** `app`:

```bash
# Импорт за последние 3 года (по умолчанию)
docker exec finforme-app-1 ./import-rates-history

# Или за конкретный период
docker exec finforme-app-1 ./import-rates-history -from 2020-01-01 -to 2026-04-04
```

### Blue Dollar Sell: история с июня 2023 года

`import-blue-rates` читает исторический график Sell с
[bluedollar.net](https://bluedollar.net/informal-rate/) и существующие курсы
`USD/RUB` источника `cbr` из базы. Утилита запускается вручную из исходников
и не входит в Docker-образ приложения. Перед запуском задайте `DATABASE_DSN`
для нужной MariaDB. По умолчанию выполняется только проверка:

```bash
go run ./cmd/import-blue-rates -from 2023-06-01 -to 2026-09-12
# Запись после успешной проверки:
go run ./cmd/import-blue-rates -from 2023-06-01 -to 2026-09-12 -apply
# Исходные котировки для конкретных дат (без записи):
go run ./cmd/import-blue-rates -quotes 2024-07-08,2025-01-24
```

Без `-to` используется текущая дата UTC. Даты раньше 2023-06-01 и будущая
конечная дата запрещены. `-html /path/source.html` позволяет использовать
сохранённую страницу; её JavaScript не исполняется. Программа возвращает JSON.

Данные записываются одной транзакцией, повторный запуск не создаёт дублей:

- `USD/ARS`, источник `bluedollar_sell`: песо за доллар, только даты источника;
- `RUB/ARS`, источник `cross_blue_sell`: песо за рубль, каждый календарный день.

Официальные ряды `bcra`, `cbr` и `cross` остаются нетронутыми. Для каждого дня
независимо выбираются последние котировки Blue и ЦБ на эту дату или раньше.
При отсутствии котировки или давности больше 14 дней импорт завершается
ошибкой до записи; будущие значения и интерполяция не используются.

Для расходов применяется `RUB = ARS / blue_sell × cbr_usd_rub`.
`exchangerates.Quote.RUBCents` считает через точные дроби и округляет только
конечный результат до копейки (половина вверх). Округлённый до шести знаков
курс `RUB/ARS` предназначен для хранения/графиков, не для расчёта суммы.
`-quotes` возвращает исходные ставки и даты для сохранения происхождения
оценки в транзакции. Сам загрузчик **не меняет транзакции**, не включает
автоконвертацию и не добавляет регулярное обновление Blue в cron.

Перед загрузкой новых источников разверните версию страницы курсов,
которая различает графики по паре **и источнику**.

Для явно согласованной замены официальных ARS-курсов до сентября 2025:

```bash
# Только аудит рабочей базы (имя, диапазоны, отсутствующие даты):
go run ./cmd/import-blue-rates -audit
# Предпросмотр и резервная копия (файл должен быть новым):
go run ./cmd/import-blue-rates -from 2023-06-01 -to 2025-08-31 -replace-official -backup /tmp/rates-preview.json
# Применение с отдельной резервной копией:
go run ./cmd/import-blue-rates -from 2023-06-01 -to 2025-08-31 -replace-official -backup /tmp/rates-before.json -apply
```

В этом режиме удаляются **только** `USD/ARS/bcra` и `RUB/ARS/cross` внутри
заданного периода. Вместо них сохраняются ежедневные `bluedollar_sell` и
`cross_blue_sell`; выходные заполняются предыдущими известными котировками.
Курсы ЦБ `USD/RUB` и записи вне периода сохраняются. До фиксации транзакции
проверяются все новые суммы и неизменность остальных записей таблицы.
Резервная копия JSON содержит исходную таблицу курсов и использованные
котировки с датами; её нужно перенести из временной папки в постоянное хранилище.
Восстановление из JSON выполняется отдельно; команды автоматического отката нет.

### Ежедневное обновление курсов (cron)

Скрипт `import-rates` запускается каждые 15 минут с 10:00 до 16:00 МСК (07:00–13:00 UTC).
Добавьте задачу в cron на сервере (`crontab -e`):

```cron
# Обновление курсов валют каждые 15 минут с 10:00 до 16:00 МСК (07:00-13:00 UTC)
*/15 7-13 * * * docker exec finforme-app-1 ./import-rates >> /var/log/import-rates.log 2>&1
```

> **Примечание:** ЦБ РФ публикует курсы в рабочие дни. В выходные и праздники
> скрипт завершится успешно, но новых данных не добавит (курс не меняется).
> Повторные запуски безопасны — `ON DUPLICATE KEY UPDATE` не создаёт дублей.

### Привязка курсов к справочнику валют

В админке на вкладке «Привязка курсов» выберите две валюты для каждой пары
и источника. Для `USD/RUB` первая валюта — USD, вторая — RUB: курс означает
количество рублей за один доллар. Порядок и коды проверяются при сохранении.
Если валюты нет в справочнике, сначала добавьте её на вкладке «Валюты».

Связи хранятся в `currency_rate_bindings` с внешними ключами на `commodities`.
Таблица создаётся при запуске приложения. Привязки задаются администратором,
общие для всех пользователей и распространяются на все даты серии, в том
числе на новые котировки. Источники одной пары привязываются независимо.
Снятие привязки не удаляет курсы; удаление курсов не удаляет привязку.
В формах новой и редактируемой операции при разных валютах счетов появляется
выбор курса. Используются только привязанные серии: последняя котировка каждого
источника не позже даты операции и не старше 14 дней. Для обратного направления
курс применяется делением. При единственном варианте он выбирается автоматически;
при нескольких источниках нужно выбрать один. Источник, дата и исходный курс
показаны в форме. Если подходящего курса нет, сумму можно ввести вручную.

Изменение даты, счетов или суммы списания обновляет автоматический расчёт.
Ручная сумма зачисления и суммы уже сохранённой операции не перезаписываются;
кнопка «Пересчитать по курсу» возвращает автоматический режим. При одинаковых
валютах второе поле не отправляется, сумма зачисления равна списанию.
Расчёт использует точное десятичное значение курса из базы и округляет результат
до копеек (половина вверх), без промежуточного округления обратного курса.
Это точность сохранённой котировки, включая её округление при импорте.

`GET /api/v1/finance/transaction/rates` принимает `credit_account`, `debit_account`
и `post_date` (`YYYY-MM-DD`). Проверяется принадлежность обоих счетов пользователю.
Ответ содержит валюты и варианты `{code, source, rate, date, inverse}`; `rate` —
строка с десятичным числом. API/MCP сохранения операций по-прежнему принимает
явную вторую сумму: автоматический расчёт выполняется в браузерной форме.

Проверка поведения формы: `node --test tests/transaction-rates.test.cjs`
(Node.js 18+); эта проверка также выполняется в CI.

### Таблица `currency_rates`

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | VARCHAR(20) | Код пары, например `USD/RUB` |
| `name` | VARCHAR(255) | Название валюты |
| `rate` | DECIMAL(18,6) | Курс к рублю |
| `source` | VARCHAR(50) | Источник: `cbr` |
| `rate_date` | DATE | Дата курса |

Первичный ключ: `(code, source, rate_date)` — позволяет хранить курс одной валюты
из разных источников одновременно.

### Импорт GnuCash и проверка данных

SQLite GnuCash и XML (обычный или gzip) используют общий атомарный импорт.
Операции с пустым описанием сохраняются. Балансы используют `quantity` в валюте
счёта; `value` используется для проверки баланса исходной операции в её валюте.
Новые валюты создаются с метаданными из файла, без подмены на RUB.
Неизвестные ссылки, циклы счетов, неверные даты и дроби, несбалансированные или
односторонние операции отменяют весь импорт, включая создание новых валют.
Глубина иерархии не ограничена прежними десятью проходами.

Приложение хранит суммы с двумя десятичными знаками. Более точные суммы и суммы
за пределами безопасного диапазона отклоняются без округления. Ценные бумаги
и товары пока не поддерживаются. Для новой валюты нужны её описание и точность
в исходном файле; ссылки на уже известные валюты допускаются без определения.
Импорт запоминает исходные идентификаторы счетов и операций отдельно для каждого
пользователя. Если хотя бы один из них уже импортирован, весь файл отклоняется
без изменений. Защита работает при переименовании файла, смене XML/SQLite и
одновременных загрузках. Изменённая книга с прежними счетами тоже отклоняется:
синхронизация и добавление только новых операций пока не реализованы.
История сохраняется после местного редактирования/удаления данных, входит в новые
JSON-копии и объединяется с существующей историей при восстановлении.
Старые импорты и старые резервные копии без такой истории автоматически не
распознаются; существующие дубликаты это обновление не удаляет.
Таблица `gnucash_import_ids` создаётся при запуске приложения; ручная миграция
не нужна.
Это импорт счетов и операций, а не полная резервная копия GnuCash (котировки,
сверка, лоты, заметки проводок и прочие специальные поля не переносятся).
Лимиты: 32 МБ на HTTP-загрузку, 64 МБ на распакованный XML.

Для диагностики существующей базы используйте `scripts/audit_finance.sql`
в сеансе только для чтения либо на копии базы. Скрипт проверяет число проводок,
ссылки и владельцев, знаменатели, баланс операций в одной валюте и отсутствие
валюты у счёта. Обменные операции не проверяются простым сложением разных валют.
Ошибочную валюту старого импорта нельзя надёжно восстановить только по текущей
базе: необходимо сравнение с оригиналом GnuCash. Автоматических исправлений нет.

Локальная проверка 2026-09-05: в `finforme.db` обнаружена одна операция с менее
чем двумя проводками; остальные проверки скрипта пройдены. В
`mybase.gnucash.sqlite` все проверки пройдены. Несмотря на имя, второй файл имеет
схему FinForMe, а не исходную схему GnuCash. Оба файла проверены без изменений;
эти результаты не описывают состояние серверной MariaDB.

Перед автоматическим развёртыванием workflow теперь требует успешных тестов,
проверки гонок, `go vet` и интеграционных тестов с временной MariaDB.

### Защита восстановления JSON

Экспорт резервной копии собирает счета, операции и проводки в одной транзакции
с блокировкой финансовых изменений пользователя. Повреждённые ссылки не
пропускаются молча: экспорт возвращает ошибку.

Восстановление принимает только режимы `merge` и `replace` (регистр и пробелы
не важны). Без режима сохраняется прежнее поведение `replace`; неизвестный режим
отклоняется. Неверные даты, повторные идентификаторы операций, нулевые/отрицательные
знаменатели, переполнение и суммы, требующие округления до сотых, отклоняются
без изменения существующих данных. Пустая дата создания в старых копиях по-прежнему
заменяется датой операции. Файл ограничен 64 МБ, multipart-запрос целиком — 65 МБ;
временные файлы формы удаляются после чтения.

Начиная с версии 2 JSON-копии дополнительно содержат `commodities`: код, пространство имён,
название, CUSIP, точность, источник и часовой пояс котировок, символ валюты.
Экспорт включает только валюты счетов пользователя. При восстановлении новые
валюты создаются со всеми этими свойствами. Если существующая валюта имеет другие
свойства, восстановление отменяется целиком; общий справочник не перезаписывается.
Создание валют при параллельных импортах сериализовано.
Копии версий 0/1 по-прежнему принимаются: если метаданных нет, для новой валюты
используются прежние значения — название равно коду, точность 100. Новые копии
нужно восстанавливать обновлённой версией приложения.
